# Experience direction

## Thesis

- **Recipient:** an architect who has a working agent workflow but cannot yet prove its deployment boundary.
- **Job:** expose the operator's real state, submit one bounded run, and inspect the signed receipt.
- **Promise:** the first screen distinguishes simulation, runtime execution, and durable evidence without revealing infrastructure credentials.
- **Primary action:** run the bounded sample workflow.
- **Signature evidence:** the returned, signed `starlight.run-receipt.v1` record.
- **Posture:** a calm instrument panel; the architecture is visible because it is actionable, not decorative.

## Three directions considered

1. **Editorial field manual** — ivory paper, annotated diagrams, long-form explanation. Strong for education; too slow for operational state.
2. **Midnight instrument panel** — near-black field, warm paper text, cyan state signals, mono receipts, restrained topology line. Selected because the product's consequence is inspection and control.
3. **Bright systems map** — white canvas with colorful provider nodes. Clear in presentations; risks making vendor logos the product.

## Selected system

The static composition carries the complete workflow. Motion is limited to state feedback: a short status pulse and progress transition. Reduced-motion removes both. Display type uses Georgia from the system stack for editorial authority; interface type uses the native UI stack; data uses the native monospace stack. No font download, license, or layout-shift dependency is introduced.
